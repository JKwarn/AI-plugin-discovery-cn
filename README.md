# AI Plugin Discovery CN

一个面向中文用户的 AI 插件与 Skill 发现平台，同时提供技术文档阅读能力。

本项目以公开的 AI 插件仓库为上游资源来源，通过自动化流程完成资源同步、元数据提取、中文辅助阅读、分类管理和趋势分析。上游仓库保持只读；本项目不修改上游文件，也不把翻译内容当作原始插件的可执行或安装内容。

## 项目目标

- **发现资源**：帮助用户按功能、使用者角色和具体场景发现插件及 Skill。
- **阅读文档**：提供中文阅读内容，同时保留英文原文和上游链接。
- **追踪变化**：记录上游版本、文件变更和资源更新状态。
- **治理分类**：通过人工审核维护可演进的分类体系，AI 仅提供候选建议。
- **分析趋势**：独立分析资源变化、分类覆盖和新兴需求，为分类调整提供证据。

## 分类维度

| 维度 | 回答的问题 | ID 前缀 |
| --- | --- | --- |
| 功能（functions） | 这个 Skill 能完成什么类型的工作？ | `function.` |
| 角色（roles） | 谁会从这个 Skill 中受益？ | `role.` |
| 场景（scenarios） | 用户希望完成什么具体任务？ | `scenario.` |
| 标签（tags） | 还有哪些值得关注的特征？ | `tag.` |

分类允许多级层次（tags 首期保持扁平）。Skill 是首要分类对象；Plugin 页面可由其包含的 Skill 聚合分类信息。分类关联需有明确依据，正式展示只使用审核通过的关联。

## 数据来源

- 首选上游：[`cursor/plugins`](https://github.com/cursor/plugins)
- 上游仅作为只读数据源。
- 每次同步应记录上游 Git commit revision；每个资源文件可记录内容 hash。
- 具体插件的清单格式和版本应分别记录，不能把不同 manifest 路径的版本混为一谈。

## 项目状态

当前处于**基础结构与数据规范建设阶段**。数据模型和 JSON Schema 尚未冻结；自动化工作流、网站和公开数据集将在基础校验稳定后逐步加入。

## 计划中的主要模块

- `data/`：上游来源、Plugin、Skill、分类、分类关联、提案与趋势报告。
- `schemas/`：结构化数据的 JSON Schema。
- `scripts/sync/`：上游同步与资源变更检测。
- `scripts/translate/`：中文阅读内容生成。
- `scripts/classify/`：分类建议生成。
- `scripts/validate/`：数据与引用完整性校验。
- `scripts/analyze/`：独立的分类趋势分析。
- `docs/`：架构、数据规范和维护流程。
- `.github/workflows/`：后续承载 GitHub Actions 自动化。

## 基本原则

1. 不修改上游仓库。
2. 保留英文原文和原始文件链接。
3. 中文翻译仅用于阅读，不替代原始资源。
4. AI 可以提出建议，但不能绕过人工审核修改正式分类。
5. 分类 ID 稳定；合并、拆分和弃用必须保留迁移记录。
6. 所有自动化结果均可追溯到上游 revision 和本项目数据版本。

## 维护方式

项目以 GitHub 网页维护和 GitHub Actions 自动化为主要工作方式。涉及正式分类、Schema 或自动化逻辑的变更应通过 Pull Request 审查。
